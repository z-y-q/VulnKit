## 安装

1. 打开 Chrome，地址栏输入 `chrome://extensions/`
2. 右上角开启「开发者模式」
3. 点击「加载已解压的扩展程序」，选择本项目目录
4. 安装完成后，点击浏览器右上角扩展图标即可使用

## 1. 编码工具

常用的编解码工具，支持 4 种格式：

| 格式 | 编码方向 | 解码方向 | 适用场景 |
|------|---------|---------|---------|
| Base64 | 文本 → Base64 字符串 | Base64 → 原始文本 | 解码 JWT、解码隐藏参数 |
| URL | 特殊字符 → `%XX` 编码 | `%XX` → 原始字符 | 构造/解码 URL 参数 |
| HTML | `<>&"'` → 实体编码 | 实体 → 原始字符 | XSS 测试时编解码 |
| Hex | 文本 → 十六进制 | 十六进制 → 文本 | 分析二进制数据、颜色值 |

**使用方法：**
1. 选择对应的编码类型（Base64 / URL / HTML / Hex）
2. 在「输入」框输入内容
3. 点击「编码」或「解码」
4. 结果显示在「输出」框中，可一键复制

## 2. 图标识别

提取网站 Favicon 图标并计算 MurmurHash3 哈希值，一键在各大资产测绘平台搜索关联资产。

**使用方法：**
1. 输入目标网站 URL（或自动获取当前页面）
2. 点击识别，自动提取 Favicon 并计算 `icon_hash`
3. 显示 5 个平台的搜索链接，点击即可跳转：
   - **FOFA** — `icon_hash="-xxx"`
   - **ZoomEye** — `iconhash:"-xxx"`
   - **Shodan** — `http.favicon.hash:xxx`
   - **Censys** — 资产搜索
   - **Hunter** — 资产搜索

**用途：** 通过 Favicon 哈希快速找到使用相同框架/模板的其他站点，扩大攻击面。

## 3. 信息收集

一键提取当前页面源码中的敏感信息，分为 5 个类别：

| 类别 | 提取内容 |
|------|---------|
| API 接口 | 源码中 `/api/`、`/v1/`、`/v2/` 等接口路径 |
| 域名 | 页面中引用的所有外部域名 |
| 敏感信息 | 手机号、邮箱、身份证号、内网 IP |
| IP 地址 | 公网 IP 和内网 IP（10.x / 172.16-31.x / 192.168.x） |
| 注释内容 | HTML 注释 `<!-- -->` 中的开发者备注、TODO、敏感信息 |

**使用方法：**
1. 在目标页面打开插件
2. 点击对应类别的「提取」按钮
3. 结果逐条显示，可复制

## 4. 资产测绘

集成 FOFA、ZoomEye、Shodan 三大资产测绘平台，在插件内直接搜索。

**使用方法：**
1. 切换到对应平台标签（FOFA / ZoomEye / Shodan）

4. 点击搜索，结果以表格形式展示（IP、端口、标题、协议等）

**提示：** 各平台 API Key 注册账号后在个人中心获取。

## 5. 链接提取

**提取范围：**

- `<script src>` — JS 文件
- `<link href>` — CSS/图标
- `<img src>` — 图片
- `<iframe src>` — 内嵌页面

**使用方法：**
1. 打开目标页面后点击插件
2. 选择要提取的链接类型
3. 支持关键词过滤和去重
4. 一键复制所有提取结果

## 9. 请求伪造

包含 3 个子功能：UA 切换、Cookie 管理、Header 伪造。

### 9.1 UA 切换

伪装浏览器的 User-Agent 标识。

**内置 19 种预设 UA：**
- Chrome / Firefox / Safari / Edge（Windows / Mac / Linux / Android / iOS）
- 搜索引擎爬虫：Googlebot、Bingbot
- 自定义 UA：手动输入任意 UA 字符串
- 恢复默认：一键还原浏览器原始 UA

**使用方法：** 在下拉列表选择预设 UA，或输入自定义 UA，点击应用即可。设置后所有请求都会携带新的 UA。

### 9.2 Cookie 管理

查看、编辑、删除当前站点的 Cookie。

**功能：**
- 列表显示所有 Cookie（名称、值、域名、路径、Secure、HttpOnly）
- 添加/编辑单个 Cookie
- 删除单个或全部 Cookie
- 导出 Cookie 为 JSON / 从 JSON 导入

### 9.3 Header 伪造

伪造 HTTP 请求头，绕过基于请求头做鉴权的服务端校验。

**常用伪造头：**
- `X-Forwarded-For` — 伪造来源 IP
- `X-Real-IP` — 伪造真实 IP
- `Referer` — 伪造来源页面
- `Origin` — 伪造请求源
- `Client-IP` — 伪造客户端 IP

**使用方法：** 输入 Header 名称和值，点击添加。所有后续请求都会自动携带伪造的头。

## 10. Vue 分析

> **这是插件的核心功能**，专为渗透测试 Vue.js 管理后台设计，可以检测 Vue 应用、拦截权限菜单、发现隐藏路由、绕过权限控制。

### 整体思路

很多后台管理系统使用 Vue + 路由守卫控制菜单显示。前端路由表中定义了所有页面路径，但后端只返回当前用户有权限看到的菜单项。通过以下步骤可以发现并访问没有权限的页面：

```
检测 Vue → 拦截菜单 API → 分析权限数据 → 对比路由差异 → 修改菜单数据 → 访问隐藏页面
```

### 10.1 基础检测

检测当前页面是否为 Vue 应用，获取框架版本和核心实例信息。

**检测内容：**
- **Vue 版本** — 自动识别 Vue 2 或 Vue 3
- **Router 实例** — 是否使用了 Vue Router，获取路由表
- **Store 实例** — 是否使用了 Vuex 或 Pinia 状态管理
- **路由列表** — 导出所有路由路径（包括动态添加的 `router.addRoute()` 路由）
- **路由元信息** — 显示 `meta.roles`、`meta.permissions`、`meta.hidden` 等权限相关字段

**使用方法：**
1. 在目标 Vue 后台页面打开插件 → 切换到「Vue 分析」→「基础检测」
2. 点击「检测 Vue」
3. 查看检测结果，确认 Vue 版本和路由信息
4. 点击「导出路由」可复制所有路由路径

**相关按钮：**
- **检测 Vue** — 执行检测
- **导出路由** — 复制所有路由路径到剪贴板
- **绕过路由守卫** — 注入脚本禁用 `router.beforeEach` 中的权限检查，让所有路由可访问
- **复制结果** — 复制检测结果文本

### 10.2 权限菜单（核心功能）

拦截页面中权限/菜单相关的 API 响应，分析并修改菜单数据，实现「上帝视角」。

#### 第一步：拦截 API

**使用方法：**
1. 切换到「权限菜单」标签
2. 点击「开始拦截」
3. **刷新目标页面**（这一步很重要，拦截器需要在页面加载时注入才能捕获 API 响应）
4. 页面加载完成后，捕获到的菜单/权限 API 会自动显示在列表中

**拦截范围：**
- 自动拦截所有 `fetch` 和 `XMLHttpRequest` 请求
- 过滤包含 `menu`、`permission`、`role`、`auth`、`getMenuList`、`getRouters` 等关键词的 API
- 显示：请求 URL、数据大小、自动分类标签

#### 第二步：分析数据

点击列表中的任意一条捕获记录，进入详情视图：

**自动分类：**
- **全开放** — 所有菜单项都已返回，无隐藏
- **半开放** — 部分菜单可见，部分被隐藏
- **特殊0开放** — 返回空数组 `[]`，但路由中实际定义了页面（接口可能做了严格的权限校验）
- **其他** — 非菜单类响应

**操作建议：** 系统会根据分类自动推荐下一步操作（高亮推荐按钮）。

#### 第三步：修改数据

在 JSON 编辑器中可以手动编辑菜单数据，也可以使用以下快捷操作：

| 按钮 | 功能 | 适用场景 |
|------|------|---------|
| **全部显示** | 将所有 `hidden: true` 改为 `false`，移除权限限制 | 菜单数据中所有项都存在但有隐藏标记 |
| **提权至管理员** | 将 `isAdmin`/`role`/`isSuperAdmin` 等字段改为管理员值 | 响应中包含角色/管理员字段 |
| **展开 menuIds** | 收集所有菜单 ID 并展开为完整 ID 列表 | 使用数字 ID 控制菜单权限的系统 |
| **应用修改** | 将修改后的数据注入到页面（Vuex/Pinia + localStorage） | 所有修改完成后点击此按钮生效 |

#### 第四步：应用修改

点击「应用修改」后，插件会：
1. 将修改后的菜单数据写入 Vuex/Pinia Store
2. 同步更新 localStorage/sessionStorage 中的菜单缓存
3. 页面会自动显示新的菜单项

**应用后：** 点击页面上的菜单或刷新页面，检查是否出现了之前没有的新菜单项。

#### 自动搜索（0开放场景）

当分类为「特殊0开放」时（接口返回空数组），系统提供「自动搜索」功能：
1. 自动用 `menu`、`routes` 等关键词搜索页面 JS
2. 从已捕获的 API URL 中提取关键词继续搜索
3. 在 JS 源码中寻找菜单/路由定义，帮助发现隐藏功能

### 10.3 JS 搜索

在页面的所有 JS 文件（包括内联和外部引用）中搜索关键词。

**使用方法：**
1. 切换到「JS 搜索」标签
2. 在搜索框输入关键词，或点击预设关键词快捷搜索
3. 搜索结果显示匹配的文件路径、代码上下文、关键词高亮

**预设关键词：** `menu`、`permission`、`menuList`、`routes`、`isAdmin`、`isadmin`、`role`、`menuIds`

**用途：** 在 JS 源码中搜索权限控制相关代码，了解菜单/路由定义和权限校验逻辑。

### 10.4 路由对比

对比 Vue Router 中定义的路由和实际显示的菜单，发现隐藏路由。

#### 路由对比

**使用方法：**
1. 切换到「路由对比」标签
2. 点击「开始对比」
3. 系统自动对比 Router 路由表与菜单数据
4. 结果分两组显示：
   - **隐藏路由** — 路由存在但菜单中未显示（红色标记 `[隐藏]`）
   - **已显示路由** — 菜单中可见的路由（绿色标记 `[显示]`）

**操作按钮：**
- **复制隐藏路由** — 将所有隐藏路由路径复制到剪贴板
- **一键补全到菜单** — 自动将所有隐藏路由注入到当前选中的菜单数据中

#### 自动遍历（配合 Burpsuite 抓包）

自动逐个访问隐藏路由，配合 Burpsuite 抓包检测未授权访问。

**使用方法：**
1. 先执行「路由对比」获取隐藏路由列表
2. 在下方「自动遍历路由」区域设置参数：
   - **间隔时间** — 每次跳转的等待时间（默认 3 秒）
   - **仅隐藏路由** — 只遍历菜单中未显示的路由（推荐，默认开启）
3. 点击「开始遍历」
4. 插件自动逐个通过 `$router.push()` 访问路由
5. 遍历日志实时显示每条路由的跳转结果
6. 配合 Burpsuite 抓包，分析每个路由是否返回了未授权数据

**停止：** 点击「停止」按钮可随时中断遍历。

### 10.5 典型使用流程

**场景一：普通后台，菜单部分可见**

```
1. 基础检测 → 检测 Vue
2. 权限菜单 → 开始拦截 → 刷新页面
3. 点击捕获到的菜单 API → 查看分类（半开放）
4. 点击推荐操作「对比并补全缺失菜单」
5. 点击「应用修改」→ 页面出现新菜单
```

**场景二：接口返回空菜单（0开放）**

```
1. 基础检测 → 检测 Vue → 导出路由
2. 权限菜单 → 开始拦截 → 刷新页面
3. 点击捕获到的 API → 分类显示「特殊0开放」
4. 点击「自动搜索」→ 在 JS 中寻找菜单定义
5. 在搜索结果中分析路由和权限逻辑
6. 路由对比 → 开始对比 → 获取隐藏路由
7. 自动遍历 → 开始遍历 → 配合 Burpsuite 检测未授权
```

**场景三：需要绕过路由守卫**

```
1. 基础检测 → 检测 Vue → 点击「绕过路由守卫」
2. 权限菜单 → 开始拦截 → 刷新页面
3. 应用修改后，直接在浏览器地址栏输入隐藏路由路径访问
```

## 常见问题

**Q: 插件安装后点击图标没有反应？**
A: 请确认已开启「开发者模式」，并且选择的目录包含 `manifest.json` 文件。

**Q: Vue 分析检测不到 Vue？**
A: 确保目标页面确实是 Vue 应用（查看页面源码是否有 `__vue__` 或 `data-v-` 属性）。部分 SPA 应用需要在页面完全加载后再检测。

**Q: 权限菜单拦截不到数据？**
A: 必须在点击「开始拦截」后 **刷新页面**，拦截器需要在页面加载时注入才能捕获初始化时的 API 请求。

**Q: 应用修改后页面没有变化？**
A: 尝试手动刷新页面。如果仍然无效，可能是应用使用了不同的状态管理方式，可在 JS 搜索中搜索 `store` 或 `commit` 了解应用的 Store 结构。

**Q: 自动遍历时页面跳转报错？**
A: 部分路由可能需要特定参数（如 `/user/:id`），这类动态路由无法直接访问，属于正常现象。

**Q: Burpsuite 如何配合自动遍历？**
A: 先在 Burpsuite 中配置好代理，浏览器通过代理访问目标站点。点击「自动遍历」后，所有路由请求都会经过 Burpsuite，在 HTTP History 中逐条检查响应内容即可。
